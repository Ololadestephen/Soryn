# Future token-associated progression — design note only

Not implemented by the presentation/difficulty milestone. Current combat provides verified holder access and private token-associated battle records. There is no persistent fighter progression, configurable combat equipment/loadout system or combat ghost training.

A later authorized design could add cosmetic achievements, consented published match chapters and explainable ghosts frozen from explicitly consented combat history. Prefer learning new tactical options over permanently inflated stats or automatic wins. NFT count and rarity must never stack power. Public history may follow token identity with contributor attribution/withdrawal; private drafts, sessions and account identifiers remain with their authors. Current-owner generations must authorize every new official write, including after transfer away/back. Compare only equivalent rules/setup/difficulty cohorts, without pretending wallet count proves distinct humans or blind attempts.

Any such work needs a separate versioned specification, balance evidence, privacy/consent model and implementation authorization. No contract/NFT metadata mutation, custody, financial rewards, staking or transfers are proposed for this note.

Private friend battles are a separate local milestone. Public matchmaking, rankings, rewards, wagers, progression, and combat ghosts stay deferred. See [private friend battles](PRIVATE_PVP.md). The current friend-match rules are not a balance claim.
