## Phase 2 — ghost and museum

- Derive a bounded strategy profile from recorded action observations with explicit support counts.
- Create immutable GhostVersion with deterministic decision rules and disclosed confidence/support, including fallback behavior for unseen states.
- Evaluate player and ghost separately from the same initial scenario; don't interleave their actions into a different environment.
- Allow replaying an exact recorded run and racing a strategy ghost; label the two modes distinctly.
- Publish a failure exhibit only after consent, server validation and terminal outcome.
- Share challenge links with frozen scenario/rules versions. Separate fresh attempts from known retries; disclose that unseen exposure cannot be proven.
- Persist completed attempts, ghost versions and public exhibits; retry operations must be idempotent.

Gate: another browser can open a challenge, play the same scenario and inspect how outcomes differed. Same inputs reproduce identical gameplay results; timestamps/storage IDs need not be byte-identical.

## Risks and pre-decided responses

- NFT integration unverified: continue labelled guest work, escalate verification gap; do not fabricate collection configuration.
- No holder available: offer public guest demo and local transfer tests while seeking consenting holder validation; disclose remaining real-holder coverage.
- Ownership RPC unavailable: official writes disabled; public replays and guest practice remain usable.
- Server/database state unavailable: don't accept scored/public writes into memory as if durable; retry idempotently after recovery.
- Ghost under-supported: show fallback and support count; do not claim deep learning. Improve action diversity before adding models.
- Game boring/confusing: shorten and tune the actual mission using observed tests, not more blockchain features.
- Test cohort first attempt unverifiable: report 'first recorded attempt' and external-knowledge limitation.
